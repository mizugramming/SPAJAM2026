# SPAJAMの初期開発と引き継ぎ

目標は、主要導線が動き、別の開発者が会話履歴なしで起動・担当開発を始められること。依頼された段階まで進め、計画の依頼をアプリ実装へ広げない。

## 入口と進め方

1. `AGENTS.md`、READMEが示す現行設計・決定・環境・担当表と実ファイルを確認する。既存の技術・素材・端末条件は、そのアプリで有効かを判断する。過去アプリの見た目、固定寸法、ライブラリ、ブランチ名を新アプリの既定にしない。
2. 下表から現在必要な手順だけ読む。既に合意・実装した段階は差分確認で済ませる。通常の実装・共同開発ルールはAGENTS.mdを正本とし、ここへ複製しない。

| 場面 | 読む資料 | 到達点 |
|---|---|---|
| アイデアの受領・体験や範囲の大きな変更 | [認識合わせ](references/alignment.md) | コンセプト・主要導線・完成条件の合意 |
| 合意後の画面・データ設計と初期実装 | [設計と実装](references/design-and-build.md) | 起動から操作・実結果まで接続 |
| UI/UXを見直す・画面やボタンを一つずつ磨く | [UI/UXと操作単位の改善](references/ui-review.md) | 現物の点検 → 改善 → 同条件で再確認 |
| 素材・アニメーション・結果分岐が体験に含まれる | [素材・演出・結果の確認](references/visual-details.md) | 見た目と途中状態・実結果の整合 |
| UI確認・端末検証・分担や引き渡し | [検証と引き継ぎ](references/verify-and-handoff.md) | 証拠と再現手順を伴う引き渡し |

3. 新規案や主要体験の変更では、**コード着手前に**、理解したコンセプト・主要導線・完成条件を短く提示し、ユーザーの合意を得る。同じ範囲の明示的な合意があれば再確認しない。既存UIの改善は依頼された画面・部品と合意済みの意味を基準に進め、企画全体の再合意を求めない。合意が必要なときは回答を待ち、依存しない調査・設計案の整理を進める。時間経過を合意と扱わない。
4. 合意後は、具体案と判断理由を示して実装・検証・修正まで進める。合意を変えない微調整で停止しない。対象OS・外部費用・共通接続・完成条件を変える判断は影響を示して調整する。

## 成果物の置き場

既存の同じ役割の資料を更新する。下記は対応例で、全ファイルの新設や特定の構成を必須にしない。資料がなければ、リポジトリの `templates/project/` を必要に応じて使う。

| 内容 | 既存資料がない場合の配置例 |
|---|---|
| コンセプト、合意範囲、対象外、完成条件、判断の根拠 | `docs/app_design.md` |
| 画面と状態、テーマ・部品・文言の基準 | 同じ設計書。大きくなればUI設計を分離 |
| データ契約、機能境界、担当と親画面の組み込み | `docs/project_structure.md` |
| 固定環境、取得から起動まで、設定名と取得先 | `docs/development.md` とREADMEからのリンク |
| 実行結果、画像確認、端末と未確認事項 | `docs/validation.md` |
| 各担当の目的・編集範囲・依存仕様・完成条件・確認方法 | `docs/handoff.md`。必要なら担当ごとに分離 |

未決事項は「未確認／提案／合意済み」を区別し、必要な判断者と止まる作業を記す。資料だけで完成とせず、主要体験・共有接続・起動再現の実施結果を確認する。

## 専門的な補助手順

- 合意した方針・主要画面を別PCへZIPで渡し、開発とプレゼンを分担する場合は、[共有ZIPの手順](../spajam-share-package/SKILL.md)を使う。初期実装の完成条件とは別の共有時点として扱う。

- 制約違反・overflowの切り分けには、導入済みなら `$flutter-fix-layout-issues` を使う。全画面の寸法変更で解消しない。
- UI操作の回帰確認が必要なら、導入済みなら `$flutter-add-widget-test` を使う。追加依存は既存環境と共通管理に従い、例を本番実装へそのまま移さない。無限アニメーションには有限の `pump` を選ぶ。
- 補助SkillやMCPが使えなくても、固定SDKのCLIと既存テストでできる範囲を進め、使えない操作を明記する。
- 修正記録を渡された場合は、利用可能なら `$spajam-feedback` で根拠と適用条件を整理する。通常の画面修正を毎回振り返り作業へ広げない。
- 既存アプリを開く・開き直すだけの依頼は、利用可能なら `$spajam-run-app` を使い、認識合わせや初期実装を最初から行わない。
