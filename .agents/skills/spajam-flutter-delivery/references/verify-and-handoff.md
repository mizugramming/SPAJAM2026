# スマホ・UIの検証と引き継ぎ

## 実寸法に追従する

対象OS・端末・向き・操作方法は今回の設計から取る。論理寸法と物理解像度を分け、親の利用可能領域を `LayoutBuilder` 等で受ける。固定値はアイコン等に限り、画面全体の拡縮で不具合を隠さない。

`SafeArea`、`Scaffold`のキーボード回避、`MediaQuery`のinsets・文字拡大、スクロール・`Expanded`/`Flexible`を必要な場所で組み合わせる。共通枠の余白やinsetsを二重適用しない。共通寸法・倍率・向きの変更はAGENTS.mdに従う。

## 確認方法を目的で選ぶ

| 方法 | 確かめるもの | 代用できないもの |
|---|---|---|
| 固定SDK・ロック・静的解析 | 環境、型、API利用、解析規則 | 表示・実操作 |
| 単体・Widgetテスト | 状態遷移、失敗時保持、二重実行、入力と反映、制約違反 | 実キーボード、ネイティブ権限・機器 |
| エミュレーター／シミュレーター | OS上の遷移、キーボード、戻る、権限の一部 | 実端末の性能・カメラ等 |
| スマホ実機 | 指の操作、実OS・権限、通信・端末機能、復帰・性能 | 別機種・別OSの保証 |

実行コマンドはREADME・環境資料の正本を使う。意味のある回帰確認を選び、些細な装飾変更だけのために実装を写したテストを増やさない。ビルドと操作検証の成功は別々に記録する。

## 画面を見て修正する

1. 主要導線を実操作し、通常と重要な失敗・空状態のスクリーンショットを取得する。小さい・縦に短い領域、文字拡大、キーボード表示を必要に応じて選ぶ。寸法は確認用条件とし、本番の固定寸法にしない。
2. **画像を実際に開いて**、余白、文字の優先順位、窮屈さ、切れ・重なり、主操作と次の行動、押しやすさ、状態と文言の一致を点検する。色だけの識別、コントラスト、アイコンの意味・読み上げ名も確認する。
3. 必要な修正後、同じ状態を再取得する。重要なアニメーションは開始・途中・終了と中断後を確認し、最終静止画だけで途中のはみ出しや遮蔽を判断しない。
4. 取得・閲覧ができなければ未確認と記し、画面・操作・期待結果を引き継ぐ。「画像生成済み」を「目視確認済み」にしない。

## 必要な範囲の操作マトリクス

- 小さい画面・短い高さ・長文・最大想定件数・文字拡大でも主要情報が読め、主操作へ到達できる。
- SafeArea・システムUI・ソフトウェアキーボードと入力・決定ボタンが干渉しない。片手操作や隣接ボタンの誤タップも確認する。
- 遷移・戻る・キャンセル・連打で入力消失や二重処理が起きない。追加・変更・削除が関連画面へ反映される。
- 保存を約束するデータは再起動後も整合する。通信や端末機能があれば拒否・切断・再試行・背景化と復帰を確認する。
- 不要な項目には対象外の理由を記す。全アプリに通信や権限機能を追加しない。

記録の列：`コミット/差分識別 / 方法 / 端末・OS・文字設定・論理領域 / 操作・条件 / 期待 / 実結果 / 証拠 / 未確認・再現手順`。失敗・未実施・対象外を成功と混ぜない。実機がなければ代替環境と実機での手順を残す。

## 会話なしで渡す

担当ごとの引き継ぎに、実際の名前・パス・コマンドで次を記す。

1. 目的と利用者への結果、動く範囲、残りの担当作業。
2. 担当者・ブランチ・編集するソース/素材/テスト、親画面への組み込み担当。
3. 依存仕様・共有型・API・状態/保存の正本と、共有契約を使う短い例。
4. 完成条件、対象外、重要な境界・失敗時の挙動。
5. 取得元・基盤コミット・固定環境・依存取得・設定名・起動先・確認コマンド。秘密値は書かない。
6. 検証結果・未確認項目・既知の問題と実機での再現手順。
7. 共通部変更の相談先・場所、PR先・先行PR・統合順・検証・レビュー条件。

各担当の起動確認を環境資料へ記録する。別の開発者がまだ実行していなければ「手順作成済み・担当者の再現未確認」とする。未割当なら境界と提案担当を示すが、分担開始可能とは断言しない。

初期実装の完了は、主要導線の実結果、デザイン/部品/データ/機能境界の整合、起動再現と担当作業への着手条件で判断する。不足があれば完了範囲と残る条件を明示する。
