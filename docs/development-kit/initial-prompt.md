# 本選用・穴埋め式の初期プロンプト

Skills一式を配置した本選アプリの作業フォルダで、下のブロックをコピーしてCodexへ送ります。`［…］` を分かる範囲で書き換えてください。まず「アイデア」の項目を埋め、ほかは「未定」「お任せ」「なし」でも構いません。

Claude Codeでは先頭の `$spajam-flutter-delivery` を `/spajam-flutter-delivery` に置き換え、残りは同じ内容を使います。[初回準備と読み込み確認](claude-code.md)を済ませてから開始してください。

端末は [事前登録](devices.md) を参照するため、機種名の入力は不要です。画像がある場合は添付や資料の場所を伝え、参考にする点と素材として使うものを区別します。

```text
$spajam-flutter-delivery を使って、本選アプリの初期開発を進めてください。
AGENTS.md・README・事前登録の利用端末を確認し、既知の情報は使ってください。
未定の項目には具体案を添えて、実装や完成条件を左右する点だけまとめて質問してください。

【アイデア】
大会のテーマ：［テーマ］
作りたいアプリ：［何をするアプリか、自由に説明］
使う人・場面：［誰が、どこで、どんなときに使うか］
一番大切な体験：［解決したいこと、使った後に感じてほしいこと、絶対に見せたい場面］

【実装範囲・開発条件：分かるところだけ】
必ず動かしたいこと：［本選で実際に操作・実演したい範囲。未定なら提案してほしい］
今回は作らないもの：［対象外の機能。未定でも可］
残り時間：［初期実装まで／大会終了まで、何時間あるか］
チームと分担：［人数、自分の担当、ほかの人へ渡したい範囲。未定でも可］
追加の端末・OS・使用台数：［登録済み端末以外の条件があれば記入。なければ変更なし］
通信・外部サービス：［通信環境、使いたいサービスや端末機能、費用の制約。未定でも可］
大会条件・設計メモ：［提示できる資料や内容。なければ未提供］

【世界観・デザイン：未定なら提案してほしい】
感じてほしい印象：［例：落ち着く、遊び心がある、活気がある。理由や利用場面もあれば記入］
こだわりたい点：［色・書体・構図・文言・演出など。特になければお任せ］
参考画像・使う素材：［なし／添付あり／資料の場所］
画像の扱い：［画像がある場合だけ、雰囲気の参考／配置の指定／そのまま使う素材を記入］
取り入れたい点・変更してよい点：［画像がある場合だけ、配色・タッチ・文字・構図などを説明］

【進め方と完成条件】
まず、理解したコンセプト・主要導線・今回の完成条件・デザインの方向を短く提示してください。
必要な認識合わせを済ませてからコードに着手し、合意済みの範囲は細かな判断で止めず進めてください。
主要体験を動かし、配色・日本語フォント・画面構成・各ボタン・文言まで磨いてください。
画面と実操作で確認し、実機を使えない場合を含め、確認できたことと未確認を分けてください。
デザインの基準、共通部品、データの扱い、機能の境界を整え、
ほかの開発者がこの会話を読まずに起動・担当開発を始められる資料まで用意してください。
```

最初の提案を確認したら、例えば「この主要導線で進めてください。見た目は案Aを採用し、一覧部分を別の開発者へ渡せる形にしてください」と返して進めます。すでに合意した内容は繰り返し確認しません。

基盤ができた後に各担当者が作業を始めるときは、既存の `docs/ai_prompts.md` の担当作業用プロンプトを使います。この穴埋め式は、アイデアを伝えて初期開発を始めるためのものです。
