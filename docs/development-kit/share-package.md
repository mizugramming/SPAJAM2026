# 方針が固まったら別PCへZIPで渡す

`spajam-share-package` は、開発とプレゼン作りを並行して進めるためのSkillです。コンセプト・主要導線・スマホ画面の方針が合意できたら、アプリが完成する前に利用できます。既存の初期実装完了条件とは別の共有時点です。

## 本番での入力

Codexでは次を渡します。Claude Codeでは先頭を `/spajam-share-package` に置き換えます。

```text
$spajam-share-package
ここまで合意した方針とスマホ画面を、別PCへ渡すZIPにまとめてください。
開発と発表までの予算は24時間で、開発を続けながら別PCでプレゼンを作ります。
既知のコンセプト・主要導線・画面方針を使い、確定と暫定、動くものと予定を分けてください。
プレゼン担当がアプリを起動せずに着手できる資料・画面・素材と、
開発側の残作業・共有契約・次の更新時点を残してください。
ZIPを別フォルダへ展開し、参照先と必要な資料を確認するところまで進めてください。
```

時間・担当・発表条件が既に会話で分かっていれば聞き直しません。足りない条件には案を添えます。上記は今回の24時間という条件を含む例で、大会の公式制限や残り時間を自動確定するものではありません。

## ZIPと受け手の作業

```text
checkpoint-01.zip
├── START_HERE.md        最初に読む案内
├── MANIFEST.json        版・基準コミット・各ファイルのハッシュ
└── project/             選択した資料・画面・素材・共通Skills
    └── docs/sharing/    コンセプト、画面方針、現状、担当と変更履歴
```

- プレゼン担当：入口からメッセージ・主要画面・デモ順を読み、資料の構成と編集を始める。Flutter環境は必須にしない。実画面・ワイヤーフレーム・未実装を区別する。
- 開発担当：担当の仕様・ファイル・接続と完成条件を読み、GitHubの基準コミットから担当ブランチで続ける。必要なソースは共有対象へ追加できる。
- Claude/Codex：展開した `project/` を開く。どの担当を進めるかを伝え、引き継ぎ資料を読み込ませる。ZIPに含まれるツールやSkillsの利用と、そのPCのSDK・認証・実機確認は別に確認する。

ZIPにはGit履歴を含めません。ZIPを渡すだけで継続同期は始まらないため、版番号と変更表で更新箇所を知らせます。既存作業へZIP全体を上書きせず、Git側で差分を確認して統合します。

## 作成と確認

`.agents/skills/spajam-share-package/assets/` の雛形を、AIが今回の実ファイルに合わせて埋めます。`share-plan.json` は含める相対パスを明示する選択リストです。フォルダの再帰選択はできますが、ルート全体・絶対パス・`..`・ワイルドカードは指定しません。参照する画像やソースも必要なものだけ追加します。

```bash
python3 .agents/skills/spajam-share-package/scripts/build_package.py --plan docs/sharing/share-plan.json --output out/share-packages/checkpoint-01.zip
python3 .agents/skills/spajam-share-package/scripts/build_package.py --verify out/share-packages/checkpoint-01.zip
```

Python 3.12以降・標準ライブラリのみです。ツールは未選択のローカルMarkdown参照や、秘密ファイル・キャッシュ等の除外、危険なパス、内容のハッシュ、既存ZIPの保護を確認します。設定内容の網羅的な秘密情報検出、画像の意味、実機動作、受け手の着手まで自動保証しません。

更新時は例えば「共有版02を作ってください。前版から変わった画面・文言・デモの箇所を一覧にしてください」と伝えます。発表前には、最終アプリの画面・実装範囲・デモと、スライド・動画の版が一致するかを照合します。

[架空案でのZIP作成・更新・受け取り試験](share-package-trial.md)に、確認した範囲と未確認を記録しています。
