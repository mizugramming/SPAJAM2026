# 提供されたUI参考資料

ユーザーが用意した [SPAJAM UI Arsenal](https://spajam-ui-arsenal.ktbys0315.chatgpt.site/) を、画面や操作を検討するための見本として使えます。このサイトの色・フォント・角丸を、次のアプリの必須条件にはしません。

2026-11-20に公開HTML・JavaScript・CSSを取得し、ブラウザーで表示を確認しました。その時点の公開画面には44件の選抜サンプルがありました。公開内容は更新されるため、この数を固定のカタログ件数にせず、採用する見本をその都度確認します。全サンプルの操作を検証したという記録ではありません。

| 見本名の例 | 参考にできる操作・状態 |
|---|---|
| 追加ボタンが数量コントロールへ変わる | 追加から数量変更へつながる操作 |
| 長押しで確定 | 押している途中・確定・途中でやめる操作 |
| 即時反映して失敗時に戻すお気に入り | 操作への即時反応と失敗後の復元 |
| 未保存の変更がある画面からの退出 | 戻る操作と編集内容の保持 |
| スクロール方向で出入りする下部バー | 内容の表示領域と主要操作への到達 |

## 見本を実装へつなぐ

1. 見本名か画面上の位置と、採用したい点を確認する。見た目・動き・操作のどれを参考にするかを分け、URLだけでアプリ全体の世界観を確定しない。
2. 対象の見本をブラウザーと必要なソースで確認し、通常・操作中・完了・中断・失敗のうち必要な状態を拾う。画像1枚だけから動きや処理を推測しない。サイトが読めない環境では、該当部分の画像・短い動画・コードなど、判断に不足する資料だけを依頼する。
3. アプリの目的、既存テーマ、端末条件、共有データに合わせ、Flutterの部品・状態・アニメーションへ設計し直す。Web用HTML/CSS/JavaScriptをそのままDartへ貼り付けない。
4. 見本内の疑似的な「送信完了」などは実処理の存在を証明しない。実アプリでは実際の更新・保存・失敗・再試行と表示を結び付ける。
5. 同じ条件の画像・実操作で、読みやすさ、押しやすさ、反応、中断、二重実行、必要な動作軽減を確認する。マウスでの確認をスマホ実機の確認と混同しない。

採用した見本名・確認日・取り入れる点・変更する点をアプリの設計資料へ記録します。コードや素材を流用するときは出典・利用条件を確認し、必要な登録を行います。カタログ全体をダウンロードしてアプリへ同梱する必要はありません。
