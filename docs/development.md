# 環境・開発手順

honsenブランチの開発手順です。現在は共通ルール・Skills・資料を配置した段階で、アプリの実装、SDK設定、依存ロックはありません。実装基盤を作る際に、実際に検証した設定とコマンドで未決定欄を更新します。バージョンは環境設定ファイルを正本とし、AIの共通ルールへ数値を転記しません。

## 日々の更新と共有前の検証

作業ブランチは `feat/<内容>`、`fix/<内容>`、`docs/<内容>` のいずれかで、1人・1タスクに分けます。未コミット変更を保護してから、自分のブランチを更新し、最新の統合先を取り込みます。

```bash
git status --short --branch
git fetch origin
git merge origin/honsen
python3 tool/check_skills.py
python3 tool/check_skills.py --self-test
python3 tool/sync_claude_skills.py --check
python3 tool/sync_claude_skills.py --self-test
git diff --check
```

上記は自分の作業ブランチで、1行ずつ実行します。競合があれば解消してから検証します。

- アプリ環境・ロック整合性のチェック：基盤作成時に決定。
- アプリの整形・静的解析：基盤作成時に決定。未実施。
- アプリのテスト：基盤作成時に追加。未実施。
- 対象プラットフォームのビルド：対象OSとSDKを決めて追加。未実施。
- 実機・ブラウザで確認する操作：主要導線の合意後に決定。未実施。

競合はファイルごとに双方の意図を確認して解消します。SDK・依存関係・ロックは各自のエラー回避のために変更しません。

## CI・PR・マージ

- 初期CI：`.github/workflows/check.yml` の `check` ジョブ。共通Skills・Claude用入口の同期・各検証ツールのself-test・空白チェックを実行。
- アプリ用CI：未作成。基盤作成時にローカルと同じSDK設定・依存ロックを使う解析・テスト・ビルドを追加。
- PR先：`honsen`。
- 承認レビュー：他の人の承認は必須にしない。書き込み権限を持つメンバーは自分のPRもマージできる。
- GitHubのブランチ保護：`main` の設定が自動的に `honsen` にも適用されるとは扱わない。CIの実行と強制設定を区別し、実際の設定を確認する。
- マージ前の確認：マージする人が、最新コミットの `check` 成功、差分、競合の有無、未解決のレビュー会話を確認する。

SkillsのCI成功を、アプリの動作確認として扱いません。アプリ実装を始めたら、アプリ用の解析・テスト・ビルドをCIへ追加します。`tool/check_kit.py` は共通キットの `main` 用であり、`honsen` とその作業ブランチの検証では実行しません。アプリファイルを追加できます。GitHubの保護を導入・変更する場合は、実際の設定とこの案内を揃えます。

```bash
gh pr create --base honsen
gh pr checks --watch
gh pr merge --merge
```

push済みの作業ブランチで実行します。既存PRがあれば作成し直さず更新します。CIが未実行・失敗・実行中ならマージせず、原因を確認します。管理者による迂回操作は通常手順に含めません。

PRは順番に統合し、先行PRが入ったら後続PRは `origin/honsen` の取り込み・再検証・pushを行います。アプリの配布・リリース先と手順は未決定です。
