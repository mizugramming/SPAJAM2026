# REDMI Note 15 5Gで声・往復・手触りを確かめる

素材選択画面右上の「設定」から「端末の計測」を開くと、1条件ずつ10秒で試せる。ゲームUIを使わずに始めるには計測専用入口 `lib/device_main.dart` を起動する。実施済みの条件と数値は[検証記録](validation.md)を参照。

## 実機で開く

1. [開発手順](development.md)に従い、登録端末にAndroid版を通常起動する。USBで実機を選び、`SIMULATE_INPUT` の指定を外す。「疑似入力」の表示があるときは実測できない。
2. 試験日、アプリのコミット、機種、Android版、文字サイズ・表示サイズ、端末の振動設定、ケースの有無を控える。端末名は機種名だけにし、製造番号・ADB識別子は記録しない。
3. 机や机の上の物との接触を避け、同じ持ち方・場所で比較する。記録は下の表に数値と短い所感を転記する。「今回の記録」は画面を閉じると消える。採音データはメモリで判定し破棄する。

## 声を測る

声域を「声が低い人」か「声が高い人」に合わせ、「声を取る」を押す。初回はマイクを許可し、約1.2秒、一定の高さで「あー」と声を出す。普段の声と低め・高めの声を同じ距離で各3回試す。会場で使う環境音の中でも繰り返し、未判定や同じ声でのやすりのばらつきを記録する。無音でも試す。

| 環境・声の条件 | 声域 | 測定Hz（3回） | 選ばれたやすり／未判定（3回） |
|---|---|---|---|
| 低め／普段／高め／無音のいずれか | 声が低い人／声が高い人 | | |

成人男女各30人が楽に発声したときの基本周波数は、平均で男性121 Hz、女性238 Hzだった。そこでゲームでは120 Hzと240 Hzを中目の目安とし、両モードで同じ音程差で目が変わるようにした。下表はゲーム用の初期設定。プレイヤーは出しやすい方を選べる。[寺澤ほか「平均呼気流率、声の基本周波数および声の強さの同時測定」](https://www.jstage.jst.go.jp/article/jjlp1960/25/3/25_3_189/_article/-char/ja)

| 声域 | 粗目 | 中目 | 細目 |
|---|---|---|---|
| 声が低い人 | 110 Hz未満 | 110 Hz以上135 Hz未満 | 135 Hz以上 |
| 声が高い人 | 220 Hz未満 | 220 Hz以上270 Hz未満 | 270 Hz以上 |

無音、雑音、大きな音でも高さが取れなかった場合は採音画面に留まることを確かめる。そのまま同じ高さの「あー」で再試行し、実測Hzの表示とやすりを確認する。マイク拒否後は設定で許可して再試行する。

基準音を使う場合は別の機器から声が低い人で100・120・150 Hz、声が高い人で200・240・300 Hzを順に1.2秒以上鳴らし、それぞれ粗目・中目・細目になるかを見る。同じ150 Hzが声が低い人で細目、声が高い人で粗目になり、Hzの表示が一致するかも記録する。次に800 Hz、無音、会場の環境音だけを試し、意図せずやすりが選ばれないか記録する。音程モニターと同じ推定範囲は65〜600 Hz。ゲームは1回の採音にわたる高さの安定性も調べる。

## 往復の4条件

「比較するやすりと仕上がり」で、最初は中目・「前半 10%」を全条件で固定する。条件を選び「計測を開始」を押すと10秒で止まる。手を動かす条件は端末を水平に保ち、机と平行に10〜20 cm程度、元の位置まで戻る動作を1往復として数える。10秒で10往復を目安に、実際に行った数を記録する。

| 条件 | 10秒間の操作 | 確かめること | 手で数えた往復 | 検出往復 | 振動指令回数 | 手で感じた振動・ずれ |
|---|---|---|---|---|---|---|
| ① 静止 | 手に持ったまま動かさない | 0往復、振動指令0 | 0 | | | |
| ② 振動のみ | ①と同じ位置・姿勢で保持 | 振動を感じても検出0往復 | 0 | | | |
| ③ 手で往復 | 自分で数えながら往復 | 実往復と検出数の差、振動指令0 | | | | |
| ④ 往復＋振動 | ③と同じ速さ・振幅・姿勢で往復 | ③との差、手を止めた間の誤加算 | | | | |

②・④は検出と独立に650 ms間隔で振動を指令する。画面に出る指令回数と実際に振動を感じたかを両方記録する。②で加算された場合は、どの時点で何回加算されたか、粗目・前半でも再現するかを控える。④は途中で手を止める回も別に取り、停止時刻と、その後の加算を確認する。

③④は普段の速さと、遊んでいて無理なく続く速い往復で1回ずつ試す。別の人が手の往復を数えると照合しやすい。計測終了後の「今回の記録」には、開始から各往復をアプリが受け付けるまでの秒数が並ぶ。止めた時刻、実往復、検出数、受付時刻を一緒に控える。端末を机に置いた場合と手に持った場合は別条件として記録する。

## 同じやすりの前半と後半を比べる

②で同じやすりを選び、「前半 10%」と「後半 90%」を順に10秒ずつ試す。画面に出たパルス長・強さと、長さ・強さの差を手で感じたかを記録する。やすりを変えて繰り返し、同じ進捗でも粗目・細目の違いが分かるかを確認する。Androidの振幅制御に対応しない機種ではパルス長が比較対象になる。

| やすり | 前半のms・強さ/255 | 後半のms・強さ/255 | 体感差、分かりにくかった条件 |
|---|---|---|---|
| 粗目 | | | |
| 中目 | | | |
| 細目 | | | |

細目の後半も確認する。幅の小さい速い動作で細かい刻みが残るか、ゆっくりした押し引きでは滑走中に長めに感じるか、停止時に振動が切れるかを記録する。

登録REDMIのAndroidはアプリからの振幅指定に非対応。「端末の既定の強さ」と表示されるので、この機種の比較欄にはミリ秒と実際の感触を書く。

## 本編で接触と質感を比較する

1. 端末を机に置いて声を取り、やすりが決まったら手に持って構えてから10秒の研磨を始める。机の少し上で、前に押したところで止める。初動で光と振動を感じるか、片道だけで研磨率が進まないか、手を止めた後に振動が残るかを記録する。
2. 真上に持ち上げて下ろし、水平な往復を再開する。上下だけでの加算、離したときの振動の残り、水平に戻った最初の反応を記録する。絶対的な高さや天板への接触は測定しない。
3. 同じやすり・近い研磨率で、ゆっくりした往復（目安1.2秒に1回）と速い往復（目安0.37秒に1回）を試す。手で数えた回数とタイミングログの `stroke=true` の数を比べる。別の回で速さをそろえ、粗目・中目・細目の刻みを触り分けられるか、同じやすりでも研磨後半に滑らかに感じるかを記録する。
4. 「ゲーム中の振動」をオフにして同じ動きを試し、往復と光・研磨率が手の動きに追従するかを確認する。②④の診断は固定長の振動を独立に出す。本編では接触が続く間の振動が複数回になるので、OSの振動件数と往復数は個別に記録する。

手触りの位置を比べるときは、同じ片道距離のまま速度を変える。片道の中央で振動し、端でいったん止めると手触りが切れるかを記録する。往復数・端末からの振動指令・手に感じた位置は別項目にする。

### かなりゆっくり滑らせる

本編で粗目を選び、片道約15 cmを1.2〜1.5秒かけて押し、同じ速さで引く。押しと引きのどちらも、滑っている途中で長めの振動を感じるか、元の位置に戻ったときに素材が削れるかを確かめる。次の片道では中央で1秒止まり、止めた間に振動が残るか、再び滑らせたときに振動が戻るかを比べる。もう1回は普段の速さから同じ低速へ移り、手触りの切り替わりを確かめる。

### ゆっくりした折り返しのずれを確かめる

本編で粗目を選び、机の上の約9 cm離した2点を目印にする。端末を机と平行に構え、片道を約0.6秒かけて滑らせ、端で一瞬（約0.2秒）止めて戻す。3往復し、押しと引きのそれぞれで「動き始め・中央・端・静止中」のどこで振動が始まり、どこで消えたかと、タイミングログから数えた往復数を控える。続けて振動オフで同じ動きをし、削れ方も比べる。

USBで判定から指令までを調べるときは、ラウンドを始める前に次を実行する。終了時は Ctrl+C を押し、`adb -d shell setprop log.tag.IromigakiTiming INFO` で次のラウンドから記録を止める。

```sh
adb -d shell setprop log.tag.IromigakiTiming DEBUG
adb -d logcat -v monotonic -s IromigakiTiming:D
```

`sensorNs` は加速度の採取時刻、`callbackNs` はアプリが通知の処理を始めた時刻、`handledNs` は振動判定・指令が済んだ時刻で、単位は起動後のナノ秒。`motorMs` は指令した波形の長さ（0は取消、nullは指令なし）。動きの証拠が途切れて取り消した場合は `reason=timeout` と表示する。`reversal` は速度の符号が変わったという推定、`stroke` は加算した往復。実際に手が折り返した時刻と筐体が揺れた時刻は別途比較する。

### 細かい動きと中速を再録する

下記の速度計測ページを `--profile short-medium` 付きで起動する。同じ姿勢で、合図に合わせて3秒静止・指2本幅で10秒往復・3秒静止・手のひら幅で中速の10秒往復を行う。1組ごとに `short.csv` と `medium.csv` が保存される。実際の往復数や折り返した時刻を照合する場合は別の人が記録する。[開発手順](development.md)で作ったJARで次を実行すると、粗目・研磨率0%での振動指令をセンサー時刻順に確認できる。`take` は保存先に置き換える。

```sh
java -cp /tmp/polish-signals.jar jp.spajam.polish_workshop.DeskHapticsCheckKt take/short.csv
java -cp /tmp/polish-signals.jar jp.spajam.polish_workshop.DeskHapticsCheckKt take/medium.csv
```

`round_trip` は往復の確定、`motor_ms` は指令の長さ（0は取消）。実際の手触りは新しいAPKで同じ動作を繰り返し、押しと引きのどこで感じたかを確認する。[今回採用した記録](validation.md)

## 速度の基準を取り直す

USBで登録REDMIを選び、PC側で専用の計測ページを起動する。ゲームと別に開くこのページが、重力込み3軸加速度のCSVをPCへ保存する。

```sh
python3 tool/speed_capture/serve.py build/speed-calibration/redmi
```

別の端末ウィンドウで次を実行する。

```sh
adb -d reverse --no-rebind tcp:18773 tcp:18773
adb -d shell am start -a android.intent.action.VIEW -d http://localhost:18773/ -p com.android.chrome
```

スマホを机と平行に構え「計測を始める」を押す。向きと距離（片道約10 cm）を揃え、画面の合図で3秒静止・10秒ゆっくり・3秒静止・10秒速く往復する。2組取り、保存順に最初の組を学習用、次の組を検証用にする。各組の保存先はPC側に表示される。記録終了後はPC側でCtrl+Cを押し、`adb -d reverse --remove tcp:18773` でこのポートを閉じる。

[開発手順](development.md)で作成したJARと、2組それぞれの `slow.csv`・`fast.csv` を使う。以下の `train` と `holdout` は各組の保存先に置き換える。

```sh
java -cp /tmp/polish-signals.jar jp.spajam.polish_workshop.SpeedFitKt \
  --slow train/slow.csv holdout/slow.csv --fast train/fast.csv holdout/fast.csv
```

CLIは本編の速度推定を再利用し、各クラスの中央値、境界、別テイクでの指示ラベルとの一致数を表示する。先頭3秒の静止区間は姿勢の初期化に使い、学習にはその後の完了した片道だけを使う。クラスが十分に分かれたとき、出力された2つの基準値を `DeskHaptics.kt` に反映する。

## 机に沿って磨く方式との比較用に残した従来版の検証

従来の3軸判定へ合成波形を入力したときの結果。水平な押し引きと真上への持ち上げを分ける試作の結果は[検証記録](validation.md)にまとめる。

| 入力 | 実測したアルゴリズム出力 |
|---|---|
| 倍音と雑音を加えた合成音 85、130、190、240、350、510 Hz | 全6音で基本周波数を推定。絶対誤差0.01 Hz未満 |
| 無音、白色雑音、連続して高さを変える合成音 | いずれもHz未判定。一定周波数で振幅を増やすと音量値が増加 |
| 100 Hzの合成3軸加速度。静止／モーター波形のみ／8往復／8往復とモーターを併用 | 検出は順に0・0・8・8往復 |
| 60 Hzの合成加速度。0.25秒周期で12往復、検出した往復ごとに振動を指令 | テンポごとの出力長・検出数と長い振動の評価は[実機・合成の検証記録](validation.md)を参照 |

端末担当の調整箇所は `android/app/src/main/kotlin/jp/spajam/polish_workshop/` にある。声は `VoiceAnalysis.kt`、机での静止計測・水平な動き・接触は `DeskMotion.kt`、往復の確定は `StrokeDetector.kt`、速度・粗さ・進捗による振動の長さと間隔は `DeskHaptics.kt`、センサー登録と実際の振動出力は `MainActivity.kt` を参照する。やすりの判定境界・削り量・パルスの基準値は `lib/game/game.dart` が持つ。実機で見つけた問題は、上の条件・再現回数・期待値とともに[検証記録](validation.md)へ追記する。
