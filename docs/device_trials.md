# REDMI Note 15 5Gで声・往復・手触りを確かめる

素材選択画面右上の「端末の入力と振動を確認」から「端末の計測」を開くと、1条件ずつ10秒で試せる。ゲームUIを使わずに始めるには計測専用入口 `lib/device_main.dart` を起動する。実施済みの条件と数値は[検証記録](validation.md)を参照。

## 実機で開く

1. [開発手順](development.md)に従い、登録端末にAndroid版を通常起動する。USBで実機を選び、`SIMULATE_INPUT` の指定を外す。「疑似入力」の表示があるときは実測できない。
2. 試験日、アプリのコミット、機種、Android版、文字サイズ・表示サイズ、端末の振動設定、ケースの有無を控える。端末名は機種名だけにし、製造番号・ADB識別子は記録しない。
3. 机や机の上の物との接触を避け、同じ持ち方・場所で比較する。記録は下の表に数値と短い所感を転記する。「今回の記録」は画面を閉じると消える。採音データはメモリで判定し破棄する。

## 声を測る

「声の高さで判定」→「声を取る」。初回はマイクを許可し、約1.2秒、一定の高さで「あー」と声を出す。普段の声と低め・高めの声を同じ距離で各3回試す。会場で使う環境音の中でも繰り返し、未判定や同じ声でのやすりのばらつきを記録する。無音でも試す。

| 環境・声の条件 | 判定方式 | 測定Hz（3回） | 音量表示%（3回） | 選ばれたやすり（3回） |
|---|---|---|---|---|
| 低め／普段／高め／無音のいずれか | 高さ／音量 | | | |

暫定境界は150 Hz未満が粗目、150 Hz以上230 Hz未満が中目、230 Hz以上が細目。声の高さが安定しない場合は「音量で判定」を選び、同じ声で音量を変えて試す。音量の境界は45%・70%、15%未満は両方式で未判定。分類は丸める前の測定値を使う。マイク拒否後は設定から許可して再採音できるかも確認する。ゲームの採音画面では「音量で選ぶ」で切り替える。

基準音を使う場合は別の機器から120・190・270 Hzを順に1.2秒以上鳴らし、粗目・中目・細目と表示されるかを見る。次に800 Hz、無音、会場の環境音だけを試し、意図せずやすりが選ばれないか記録する。音程モニターと同じ推定範囲は65〜600 Hz。ゲームは1回の採音にわたる高さの安定性も調べる。

## 往復の4条件

「比較するやすりと仕上がり」で、最初は中目・「前半 10%」を全条件で固定する。条件を選び「計測を開始」を押すと10秒で止まる。手を動かす条件は端末を水平に保ち、机と平行に10〜20 cm程度、元の位置まで戻る動作を1往復として数える。10秒で10往復を目安に、実際に行った数を記録する。

| 条件 | 10秒間の操作 | 確かめること | 手で数えた往復 | 検出往復 | 振動指令回数 | 手で感じた振動・ずれ |
|---|---|---|---|---|---|---|
| ① 静止 | 手に持ったまま動かさない | 0往復、振動指令0 | 0 | | | |
| ② 振動のみ | ①と同じ位置・姿勢で保持 | 振動を感じても検出0往復 | 0 | | | |
| ③ 手で往復 | 自分で数えながら往復 | 実往復と検出数の差、振動指令0 | | | | |
| ④ 往復＋振動 | ③と同じ速さ・振幅・姿勢で往復 | ③との差、手を止めた間の誤加算 | | | | |

②・④は検出と独立に650 ms間隔で振動を指令する。画面に出る指令回数と実際に振動を感じたかを両方記録する。②で加算された場合は、どの時点で何回加算されたか、粗目・前半でも再現するかを控える。④は途中で手を止める回も別に取り、停止時刻と、その後の加算を確認する。

③④は普段の速さと、遊んでいて無理なく続く速い往復で1回ずつ試す。別の人が手の往復を数えると照合しやすい。計測終了後の「今回の記録」には、開始から各往復をアプリが受け付けるまでの秒数が並ぶ。止めた時刻、実往復、検出数、受付時刻を一緒に控える。端末を机に置いた場合と手に持った場合は別条件として記録する。

## 同じやすりの前半と後半を比べる

②で同じやすりを選び、「前半 10%」と「後半 90%」を順に10秒ずつ試す。画面に出たパルス長・強さと、長さ・強さの差を手で感じたかを記録する。やすりを変えて繰り返し、同じ進捗でも粗目・細目の違いが分かるかを確認する。Androidの振幅制御に対応しない機種ではパルス長が比較対象になる。

| やすり | 前半のms・強さ/255 | 後半のms・強さ/255 | 体感差、分かりにくかった条件 |
|---|---|---|---|
| 粗目 | | | |
| 中目 | | | |
| 細目 | | | |

登録REDMIのAndroidはアプリからの振幅指定に非対応。「端末の既定の強さ」と表示されるので、この機種の比較欄にはミリ秒と実際の感触を書く。

最後に「ゲーム中の振動」をオンにし、素材選択に戻ってメダル・漢をそれぞれ3回磨く。ゲーム中は受け付けた往復でだけ進捗が進み、その進捗で振動が決まる。途中で手を止めて色と往復数が止まること、残り時間だけ進むこと、結果が最後の仕上がりと一致することを確認する。その後、設定をオフにして同様に試し、手の動きによる研磨が続き、振動が消えることを確認する。設定は同じアプリ起動中に有効。診断の②・④は条件自身が振動を制御する。

## 合成波形で実施した検証

端末の信号処理へ合成波形を入力して次を確認した。机・手・端末本体の振動や会場の騒音は上の実機試験で評価する。

| 入力 | 実測したアルゴリズム出力 |
|---|---|
| 倍音と雑音を加えた合成音 85、130、190、240、350、510 Hz | 全6音で基本周波数を推定。絶対誤差0.01 Hz未満 |
| 無音、白色雑音、連続して高さを変える合成音 | いずれもHz未判定。一定周波数で振幅を増やすと音量値が増加 |
| 100 Hzの合成3軸加速度。静止／モーター波形のみ／8往復／8往復とモーターを併用 | 検出は順に0・0・8・8往復 |
| 60 Hzの合成加速度。0.25秒周期で12往復、検出した往復ごとに振動を指令 | 振動オフ・オンとも12往復。ゲームはテンポに合わせてパルスを短くし、出力中と終了後55 msの自己振動を検出対象から外す |

端末担当の調整箇所は `android/app/src/main/kotlin/jp/spajam/polish_workshop/` 内の `VoiceAnalysis.kt`（高さと音量）、`StrokeDetector.kt`（重力除去・平滑化・方向反転・持続時間・振動後の除外）、`MainActivity.kt`（権限・センサー登録・出力）。ゲームの判定境界とパルスの計算は共有契約 `lib/game/game.dart` を参照する。実機で見つけた問題は、上の条件・再現回数・期待値とともに[検証記録](validation.md)へ追記する。
