# 通信版の接続とPCでの発表手順

2026-09-27。今回のスライド発表はFlutter Webを使い、Chrome・Edgeなど保存領域の異なる2ブラウザーを参加者A・Bとして左右に並べます。同じ公開通信サーバーへ接続し、操作や録画が難しい場合は1画面と自動操作のデモ相手で撮影・実演します。QRを人が読み取る場面は実写で別撮りします。Android2台の実機検証は後続の確認として残します。通常起動は通信版です。一台デモはビルド時にだけ切り替えます。発表用ルームには応援メンバーを補い、そのうち4人を自動操作のデモ相手として選べます。勝敗選択や実参加者の入力の自動化は追加しません。

**通信APIとWeb確認版は、管理者のCloudflare認証を経て公開済みです。公開Flutter Webはそのまま利用でき、Android実機2台の確認は未実施です。** [Web確認版](https://tsunagun.tsunagun-room-server.workers.dev)から通常アプリを開けます。通信APIは `https://tsunagun-rooms.tsunagun-room-server.workers.dev` です。接続先を指定せずに作ったビルドでは、ルームを作成・参加できません。

## 構成と起動

Flutterの `OnlineController` がHTTPでルーム操作、WebSocketでゲーム入力・状態受信・時刻補正を行います。Cloudflare Workersが受付を担当し、ルームごとのDurable ObjectがSQLite storageへ状態を保存してから応答します。勝敗・報酬・締切・最終集計はサーバーだけが確定します。詳細API・サーバー準備は [server/README.md](../server/README.md) を参照してください。

公開版を開くだけならFlutterのインストールは不要です。ソースから動かす場合は [.fvmrc](../.fvmrc) と [tool/toolchain.json](../tool/toolchain.json) の固定SDKを使います。以下はChromeで1画面を起動するコマンドです。通信APIのURLに参加トークンやAPIキーを付けてはいけません。

```bash
fvm dart tool/check_environment.dart
fvm flutter pub get --enforce-lockfile
fvm flutter devices
fvm flutter run -d chrome --dart-define=TSUNAGUN_SERVER_URL=https://tsunagun-rooms.tsunagun-room-server.workers.dev
```

ローカルでChrome・Edgeの2画面を使う場合は、次を起動したまま両方で `http://127.0.0.1:8080` を開きます。独立した保存領域を使い、URLのホスト名・ポートを揃えます。Webの配信URLとゲームの通信APIは別で、ゲームは引き続き公開HTTPS/WSSへ接続します。

```bash
fvm flutter run -d web-server --web-hostname 127.0.0.1 --web-port 8080 --dart-define=TSUNAGUN_SERVER_URL=https://tsunagun-rooms.tsunagun-room-server.workers.dev
```

ローカルAPI自体を検証する場合だけ `TSUNAGUN_SERVER_URL=http://127.0.0.1:8787` を指定します。カメラを使うWebプレビューはHTTPSまたはlocalhostで開きます。通常のHTTP LANページでは手入力を使ってください。Android実機は `fvm dart tool/check_environment.dart --android` で環境を確認し、起動コマンドの `-d chrome` を `-d 端末ID` へ置き換えます。両端末には同じ公開APIを指定し、端末自身を指す `localhost` / `127.0.0.1` を公開接続先にしません。配布前のdebug APK検証は次のコマンドです。配布署名済みrelease APKではありません。

```bash
fvm flutter build apk --debug --no-pub --dart-define=TSUNAGUN_SERVER_URL=https://tsunagun-rooms.tsunagun-room-server.workers.dev
```

通信なしで以前の画面を確認する場合だけ、次を使います。

```bash
fvm flutter run -d chrome --dart-define=TSUNAGUN_DEMO=true
```

このビルドの `TSUNA` コード・仮想相手・DEMOメニューは実ルームと接続しません。プロフィール・報酬は再起動で消え、通信版の参加情報・報酬を変更しません。

Flutter Webを通信API付きでビルドしてから、静的配信Workerを更新します。サーバーの公開とは別です。設定はリポジトリ直下の [wrangler.web.jsonc](../wrangler.web.jsonc) を使います。

```bash
cd server
npm exec wrangler deploy -- --config ../wrangler.web.jsonc
```

Androidのreleaseビルドも既存のdebug署名を使う検証用です。`--release --target-platform android-arm64 --dart-define=TSUNAGUN_SERVER_URL=https://tsunagun-rooms.tsunagun-room-server.workers.dev` で作ったAPKを、ストア公開用の署名済み成果物と扱いません。実機への導入・動作確認は別途行います。

## 二つのルーム

| 項目 | 通常ルーム | 「発表用ルーム」 |
|---|---|---|
| 実参加人数 | 2〜24人 | 1〜2人。1人でもデモ相手と遊べる |
| 応援メンバー | なし | 自動操作のデモ相手4人。実参加者1人の間だけ表示用の0点枠も補い、計6人 |
| ゲーム | 同チームは協力、異チームは対戦 | 実2人同士、または各デモ相手と対戦、その後に協力 |
| 完了した同じ相手との交流 | 合計1回 | 対戦1回・協力1回 |
| 実際の操作・勝敗 | 両者の入力をサーバーが判定 | 実参加者は実操作。デモ相手側だけ自動入力し、通常の判定・報酬を適用 |

チームは開始時に参加順で赤・青へ交互に振り分けます。主催者も参加者として遊べます。開始には、その時点の実参加者全員のプロフィール登録が必要です。通常ルームは2人以上で開始し、開始後の途中参加は受け付けません。発表用ルームだけは主催者1人で開始でき、交流時間内なら2人目が後から参加して初回プロフィールを登録できます。3人目や交流終了後の新規参加は受け付けません。交流時間は入口で3・5・10分から選び、開始後は共通の終了時刻へ進みます。中断と対戦の完全同点は完了回数に数えません。

発表用の応援メンバーは、実参加者1人なら5人、2人なら4人です。赤・青の表示人数を各3人に揃え、待機画面・ホームでデモの仲間と明示します。固定の4人には、赤・青それぞれ4点（子分1匹＋骨1匹）と2点（骨2匹）を設定し、初期戦力を両チーム6点ずつに揃えます。ゲーム後は実際の報酬で得点が変わり、MVP・順位・綱引きへ同じ内訳を反映します。実参加者へ子分や得点を事前配布しません。

実参加者1人のときだけ補う追加の0点枠は表示専用で、ゲーム相手には選べません。2人目が入るとこの枠だけが置き換わり、固定4人の得点・本人のQR・ルーム終了時刻は変わりません。ダミーに認証トークンやQRはありません。実参加枠は2台分のままで、ダミーが入室枠を消費しません。

## PCでの撮影手順

### 独立した2ブラウザーを準備する

今回の発表はこのFlutter Webの手順を使います。公開版を開く場合、Windowsでは [2画面起動スクリプト](../tool/open_presentation_windows.ps1) をPowerShellから実行できます。

```powershell
.\tool\open_presentation_windows.ps1
```

Chromeを優先し、なければEdgeを使います。A・Bはそれぞれ専用の保存領域を使い、次回も同じ参加情報へ戻ります。既に専用ウィンドウが起動している場合は重複起動しません。配置を変える場合は手動で調整するか、その専用ウィンドウを自分で閉じて再実行します。既定ブラウザーの保存情報は変更しません。画面倍率により位置がずれる場合は左右へ並べ直してください。Windowsのポリシーでps1を実行できない場合は設定を変更せず、下記の手動2ブラウザー方式を使ってください。

1. 同じPCでChromeとEdge、または保存領域の異なる2つのブラウザープロファイルを使います。同じプロファイルの別タブ・別ウィンドウは参加情報を共有します。二つのシークレットウィンドウも同じセッションを共有するため、分離用には使いません。
2. 両方で[公開アプリ](https://tsunagun.tsunagun-room-server.workers.dev)、または起動中のローカル配信 `http://127.0.0.1:8080` を開き、縦長の画面を左右に並べます。共通の `PhoneViewport` が暫定412×900論理pxを縦横比を保って収めるため、ブラウザーのズームを変える必要はありません。これはPC撮影用の暫定寸法です。
3. Aで「発表用ルーム」をON、交流時間10分で作成。Bで同じ5桁のルームコードを入力し、別々のプロフィールを登録します。Aは赤、Bは青です。実写の人物・ニックネーム・チーム色・左右の配置もこの対応に揃えます。
4. PCでゲームを接続するときは「ツナがる」→「相手のコードを入力する」を使い、相手のQR下にある8桁コードを入力します。入室の5桁と混同しません。実写は人がQRを見せて読み取る場面で、PCの手入力をQRカメラの動作確認として扱いません。
5. 両者が「準備OK！」を押し、対戦を録画します。両側にREBORNが必要な撮影では、対戦で双方とも止めずに落下→骨を獲得→もう一度同じ相手と接続→協力成功の順です。通常の勝敗・報酬判定を使い、結果を直接書き換えません。
6. 最後はAが「交流を終えて綱引きへ」→「綱引きスタート！」。順位まで撮影したら、両側で「ルームを閉じる」を押します。撮り直しは新しいルームで始めます。完了済みの同じ相手とのゲームは再実行できません。

### スライド用の素材構成

Flutter Webの2ブラウザーを使い、場面の切り替えは次の構成にします。

| 素材 | 画面 | 切り替え位置 |
|---|---|---|
| スタート・プロフィール・ホーム | Aの1画面録画 | 「ツナがる」で実写へ |
| 相手にQRを見せ、スマホをかざす | 実写 | 読み取る動作から相手確認へ |
| 相手確認・共通カウント・対戦 | A・Bの2画面録画 | 自分の結果へ |
| ショBONE・仲間・REBORN | Aの1画面録画 | 協力の導入では相手確認へ直接戻す |
| 協力ミニゲーム | A・Bの2画面録画 | 成功からREBORNへ |
| 大綱引き・順位 | Aの1画面録画 | 体験の締め |

場面別の短い動画として保存し、スライドの説明に合わせて再生します。2画面の同時収録では、同じ効果音が重ならないよう音声の収録元は片側に揃えます。1画面の素材を撮るときも、両方のアプリを表示したまま録画範囲だけ片側へ絞ります。Webではゲーム中にタブを切り替えたり最小化すると中断します。録画操作による影響はリハーサルで確認します。片方が成功・敗北したあとも相手の確定結果を確認してからホームへ戻ります。

Webでは、表示中にウィンドウの選択が外れた `inactive` は通信・ゲームを継続します。非表示の `hidden`・停止・切断では未確定ゲームを中断し、報酬を付けません。Androidなどネイティブの `inactive` は従来どおり停止します。これはPCの2画面操作のための区別で、時計や勝敗のルールは変えません。

## 2人での操作手順

前半は端末Aの画面を大きく説明し、相手と遊ぶ場面からA・Bを並べると流れを追いやすくなります。

| 場面 | 端末A（主催者） | 端末B |
|---|---|---|
| 入口 | 「発表用ルーム」をON、説明込みなら5分か10分にして作成 | 「ルームに参加する」を開く |
| ラベル | ニックネーム・趣味・ひとことを入力し「この缶で参加する」 | Aの待機画面の5桁ルームコードを入力し、プロフィール入力 |
| 開始待ち | 「交流をはじめる」。主催者1人でも先にホームを紹介できる | 開始を待つ、または開始後にコードで参加・プロフィール登録 |
| ツナがる | ホームの「ツナがる」で自分のQRを見せる | 「ツナがる」→「相手のQRを読み取る」 |
| 相手確認 | 表示された相手を確認し「準備OK！」 | 同じく「準備OK！」 |
| 対戦 | 共通のカウント後、自分の魚をタップで止める | 自分の魚を止める |
| 結果 | 自分の結果・子分を見て「ホームへ戻る」 | 自分側の結果・子分を確認して戻る |
| 協力 | もう一度同じ相手とQRでツナがり、準備完了 | 同左。自分の側へ届く魂を交互にタップ |
| REBORN | 骨があれば復活、なければ相手の普通の子分を迎える | 自分の所持状態に応じた結果を確認 |
| 綱引き | 期限を待つか「交流を終えて綱引きへ」。集計後「綱引きスタート！」 | 共通の開始を待ち、同じ演出を見る |
| 順位 | 「みんなの活躍を見る」 | 同じ確定集計から自分の順位を見る |

REBORNを両画面で紹介するなら、対戦では二人とも魚を止めずに落下させると、実際の判定で双方が骨を1匹ずつ迎えます。その後の協力成功で双方の骨が復活します。協力失敗も完了した交流に数えるため、そのルームで同じ協力を再試行はできません。発表用の対戦敗北では「次は協力して、元気にしよう！」と案内し、協力失敗後は再度の協力へ誘導しません。発表前に実操作を練習し、最初から試す場合は別ルームで行います。

入室は、主催者が待機画面で共有する5桁のルームコードを入力します。コードは数字5桁で表示し、コピーできます。**QRを使うのは対戦・協力する相手とツナがる場面だけです。** ホームの「ツナがる」で個人QRを見せ、もう一方がアプリ内カメラで読み取ります。カメラを許可できない・読み取りづらい場合は、QR下の8桁相手コードを手入力できます。空白・ハイフン・小文字は入力できます。外部URLを開いたり、QRに入った値で結果を決めたりしません。

## 1台でデモ相手と遊ぶ

2ブラウザーの同時操作や録画が難しい場合は、次を動画・当日の実演共通の予備手順にします。通信版の発表用ルームを使い、旧 `TSUNAGUN_DEMO=true` ビルドへ切り替える必要はありません。

1. ゲーム中なら両側の結果・中断状態を確認して終了し、使うウィンドウを1つにします。新しい発表用ルームを作り、主催者だけでプロフィール登録・開始へ進みます。
2. 「ツナがる」からデモ相手を選び、対戦します。REBORNの紹介では自分を落下させて骨を獲得し、ホームへ戻って同じデモ相手と協力します。相手側は自動操作であることをスライド・説明に明示します。
3. 協力の自分の番を操作して3レベルを成功させ、REBORN→ホーム→「交流を終えて綱引きへ」→綱引き・順位まで撮影または実演します。協力失敗も完了扱いなので、同じ流れを撮り直す場合は新しいルームを使います。
4. 1画面録画とQRの実写を用意し、実演時の予備動画も同じ構成で保存します。自動操作のデモ相手を、実参加者2人の操作として説明しません。

「発表用ルーム」でプロフィールを作り、主催者だけで「交流をはじめる」を押せます。「ツナがる」からデモ相手を選び、本人の「準備OK！」でゲームを開始します。実際の人と遊ぶときは従来どおり相手のQRを読み取ります。デモ相手ごとに対戦→協力を各1回遊べます。別の参加者が遊んでいるデモ相手は同時に選べません。

対戦のダミーはサーバーがあらかじめ決めたタイミングで停止または落下します。本人の操作を見て勝敗を選ばず、同じゲームの再接続で予定を変えません。協力はダミーの番だけ自動で成功入力し、本人の番は本人のタップで判定します。骨を持つ本人が協力に成功すれば、実参加者同士と同じREBORNになります。未確定中の切断・期限の扱いも共通です。

更新済みのWeb版・Android APKで作るルームのコードは数字5桁です。既存の英数字12桁ルームは保存期間内の参加・再接続を維持し、未更新のAndroidから作るルームも12桁のままです。更新済みクライアントは5桁・12桁の両方を受け付けます。未更新のAndroidから5桁ルームへ参加するにはAPK更新が必要です。相手のQRに併記する8桁の相手コードは別の用途なので変更しません。

## 判定と報酬

- 対戦勝利は相手の普通の子分1匹（3pt）、敗北は骨1匹（1pt）。相手の既存子分を奪いません。
- **両者落下は双方に骨1匹ずつを与えて対戦終了。再勝負しません。**
- **両者とも落下せず、サーバーが受け付けた停止時刻が同一ミリ秒なら報酬なし。双方の準備完了後に再勝負します。**
- 協力成功は各自の最古の骨1匹を普通の子分へ復活（差分＋2pt）。骨がない人は相手の普通の子分1匹（＋3pt）を迎えます。復活時は新しい骨を追加しません。
- 協力失敗は双方に相手の骨1匹（＋1pt）。親分はどの結果でも普通の姿です。
- 最終集計は普通3pt・骨1pt。プロフィール登録が済んでいない途中参加者は順位に含めません。順位は同点同順位、一覧は3位以内全員と4位以下の本人。全員0ptならMVPはありません。

綱引きは集まった仲間の成果を見せる演出で、連打や乱数で勝敗を変えるゲームではありません。主催者が一度要求した共有開始時刻から、11秒後に結果・得点を公開します。片方だけのスキップは置きません。動作軽減では移動を止めても同じ公開時刻を守り、復帰した端末は経過位置へ追いつきます。

## 切断・保存・再開

未確定のゲームで一方が切断・アプリを非表示へ移すと、交流を報酬なしで中断します。Webで表示中のウィンドウから選択が外れただけでは中断しません。通信不良を自動的な敗北にはしません。既に決まった結果・報酬は保持し、再接続するとサーバーの確定状態へ戻ります。接続失敗が続いたときは参加資格を再確認し、失効済みなら入口へ戻ります。一時的な通信障害では参加資格を消しません。両者が戻ったら新しい交流として再びQRでツナがれます。結果確定済みの場合は再戦制限が適用されます。

プロフィール、子分、確定結果、操作履歴はルーム作成から24時間でサーバーから削除します。長期アカウント履歴ではありません。端末の参加情報は `SecureOnlineSessionStore` / `flutter_secure_storage` へ保存します。ルーム作成・入室前には秘密の再試行キーも端末へ先に保存します。応答だけ失われても、再試行や再起動で同じ参加者へ戻り、参加枠を重複消費しません。秘密の参加トークンと再試行キーは本人の操作権限なので、QR・スクリーンショット・ログ・Gitへ出しません。保存失敗時はその旨を表示し、復元できたと装いません。

終了後の「ルームを閉じる」は、この端末の参加情報を消します。ほかの参加者の結果は消しません。アプリ削除・保存データ削除・別ブラウザーなどで参加情報が失われると、同じ参加者としての復元はできません。Webの保存は同じ安全なオリジン内で使い、Android実機の保存復元とは分けて確認します。コンベア配置は従来どおり端末内の別設定です。

## 確認すること

サーバーの型検査・ルールテスト・公開しないビルド・実HTTP/2本のWebSocketの統合テストは [開発手順](development.md) と [サーバー案内](../server/README.md) に従います。Flutter側は入力保持、QRの用途と手入力、重複結果・再接続、ゲームの実入力、同期演出を検証します。

今回の撮影前は同じFlutter Web版をChrome・Edgeなどの独立した2ブラウザーで開き、別々の参加者、共通の暫定412×900キャンバスの等比表示と1画面内の主操作、ウィンドウ選択切替、対戦・協力・REBORN・綱引きの同期、録画中の負荷を確認します。対戦の2つの停止操作と協力の交互入力を練習します。Windowsへマウスを2個つなぐだけでは入力先が独立しないため、1画面＋デモ相手の予備手順も通しで練習します。Android実機2台の検証では同じコミット・同じHTTPS接続先を使い、カメラの許可/拒否、両者落下、協力成功/失敗、REBORN、片方の背景化と復帰、終了時刻の集計、共通綱引き、音声・振動を確認してください。端末名・OS・文字サイズ・通信環境・確認結果を残します。ビルド成功やPCの2接続だけを「Android2台で確認済み」と扱いません。多数端末での負荷・通信遅延と、イベントでの面白さも未確認です。
