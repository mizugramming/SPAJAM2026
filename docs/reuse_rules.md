# 別のアプリで共通ルールを使う

基盤はプロジェクト作成者が用意し、各開発者が担当作業を開始するための共通セットです。アプリの実装や設計書を一緒にコピーする必要はありません。

## コピーするファイル

新しいプロジェクトのルートを基準に、同じ位置へ配置します。

| ファイル | 役割 |
|---|---|
| [AGENTS.md](../AGENTS.md) | 担当範囲・環境・素材・検証・マージの共通ルール |
| [docs/ai_prompts.md](ai_prompts.md) | AIへそのまま渡す担当作業の開始・再開プロンプト |
| [CLAUDE.md](../CLAUDE.md) | Claudeから共通ルールを参照する入口。利用する場合にコピー |
| [.github/copilot-instructions.md](../.github/copilot-instructions.md) | Copilotから共通ルールを参照する入口。利用する場合にコピー |

この案内も残す場合は `docs/reuse_rules.md` としてコピーします。これらはアプリ名・担当者名・SDKの数値・ブランチ名に依存しません。

## 資料の雛形を配置する

このキットの `templates/project/` の中身を、新しいアプリのルートへ配置します。既にREADMEや設計資料があれば上書きせず、不足する項目だけ取り入れてください。

- `templates/project/README.md` → アプリの `README.md`
- `templates/project/docs/` → アプリの `docs/`
- `templates/project/.github/PULL_REQUEST_TEMPLATE.md` → アプリの `.github/PULL_REQUEST_TEMPLATE.md`

Flutterアプリでは `templates/project/README.flutter.md` をアプリの `README.md` として使えます。汎用READMEと両方を上書きコピーせず、どちらかを選びます。Flutter用はリポジトリ取得済み・環境準備済みの開発者向けに、更新・起動・検証・PR・マージの最小コマンドをまとめています。作成者が配布前に統合ブランチ名を設定し、`docs/` の資料と揃えます。`README.flutter.md` という別名のファイルをアプリ側に残す必要はありません。

作成者が設計書・構成・担当範囲・環境手順を実際の基盤に合わせます。各担当者が書き込むためのプロンプトではありません。`templates` フォルダ全体をアプリのソースとして配置する必要はありません。

キットのルートREADME、`.github/workflows/check.yml`、`tool/check_kit.py`、リポジトリ固有の運用資料はコピー対象に含めません。`.git/` や別アプリの実装・素材・依存ロックも流用しません。

## プロジェクトごとに用意するもの

作成者が用意した基盤のREADMEに、次の情報や資料へのリンクを記載します。

- 今回の設計書と最新の決定事項。
- 実際の構成と各フォルダの責務、共通データ・画面の接続方法。
- 担当範囲、共通管理のファイル、同じ画面を分担する場合の組み込み担当。
- 固定する環境の設定ファイル、依存取得・起動・検証方法。
- 統合先とリリース先、PR・マージ手順。

SDKの数値やアプリ固有の構成は共通ルールへ書き足さず、そのプロジェクト側で管理します。ルールとプロンプトをコピーするだけで、アプリの基盤・CI・GitHubのブランチ保護が作成されるわけではありません。

## 分担を始められるか確認する

- 用意した基盤が、各開発者の準備済みの環境でREADMEの手順どおり起動する。
- SDK・依存ロックとCIのバージョンが一致し、各担当が個別に更新しなくてよい。
- 画面遷移、共有データ、必要な保存・復元が接続され、確認方法が資料にある。
- 担当別のソース・素材・テストと、親画面への組み込み担当が決まっている。
- 素材の登録・出典・表示確認の手順があり、画像追加のたびに全員が共通設定を触らずに済む。
- 設計・構成・環境資料の「未記入」が埋まり、決まっていない項目は担当作業への影響が明記されている。
- PRの宛先・必須チェック・レビュー方針を決め、GitHub上で保護設定が実際に有効になっている。

この条件を作成者が確認した基盤を各開発者へ渡します。コピーした文書だけで動作するアプリにはなりません。

各開発者はプロンプト集の開始用または再開用をそのままAIへ渡します。AIは共通ルールとプロジェクトの資料・実ファイルを確認し、まだ会話で共有されていない担当・変更内容を質問します。開発者が答えた内容からAIが対象ファイルを特定し、既存の基盤上で作業します。
