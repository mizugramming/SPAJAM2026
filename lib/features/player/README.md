# プレイヤーUIの接続依頼（松本 → 嶋本）

このフォルダは、共通基盤への接続前のUI下書きです。最新の `test-1` には共通基盤とオーナー画面が用意されていますが、プレイヤーの参加・QR読取・撮影・AI判定・画面遷移は、まだ接続されていません。

## 今回のブラッシュアップ

選択された「ナイトミッション」案を、参加・開始待ち・マップ・QR・撮影・写真確認・判定・順位・結果へ反映しました。既存の公開コンストラクタ・引数・コールバック・判定状態enumを維持しています。`PlayerPage` には任意の見出し表示設定だけを追加しています。

| デザイン | 実装 |
|---|---|
| 基本配色 | 濃紺 `#071B28`、ライム `#D8F16A`、シアン `#86D5E2`。エラーはコーラルと文言・アイコンで表示 |
| 担当専用テーマ | `player_night_style.dart` に色・入力・ボタン・文字の定義。`PlayerPage` のbody内へ適用し、親のフォント・文字拡大を継承 |
| 探索の雰囲気 | 薄い図面グリッド、細線のパネル、コンパス、QR／撮影枠のガイド、ミッション達成バッジ |
| マップと結果 | 残時間をライムで強調、進捗を小さめに整理、フロア選択・自分の順位・確定／仮結果を明示 |

装飾はFlutter標準の描画・アイコンだけで実装しました。画像・フォント・依存関係の登録追加はありません。注入された実案内図・カメラ映像・写真の色は加工しません。TEMPデモの設計図風マップはサンプル描画で、会場の案内図ではありません。

前回の8分野の改善も維持しています。

| 分野 | 変更内容 |
|---|---|
| 情報整理 | 参加の入力案内、お題、残時間・進捗、判定後の行動、仮／確定結果を整理 |
| 部品の見た目 | `player_ui.dart` に担当専用のページ・カード・状態表示・情報パネルを集約 |
| 操作の配置 | 通常の高さでは主操作を下部に固定。高さ不足・文字拡大時は本文と一緒にスクロール |
| マップ操作 | 1〜4倍の拡大縮小・パン・全体表示、フロアごとの表示位置保持、フロア追加削除への追従 |
| 写真確認 | 中央を基準とする拡大縮小・パン・全体表示。表示操作で提出写真を変更しない |
| 状態表示 | 撮影準備・撮影中・提出中・失敗・再接続・順位更新・仮集計を区別。既存の表示データだけを利用 |
| アクセシビリティ | 見出し、状態通知、フロア選択、自分の順位の読み上げ、確認中QR操作の除外、文字拡大対応 |
| 担当テスト | 既存8件を維持し、ズーム・失敗・遅い応答・キーボード・読み上げ・小画面等を追加 |

フォーム入力・失敗時の写真・送信中の連打抑止は維持しました。お題や写真が差し替わっても、元の撮影／提出処理が終わるまで操作抑止を維持し、前の処理のエラーを新しい表示へ混ぜません。

## 固定コースの接続順

参加 → スタートQR → 一斉開始待ち → マップ → チェックポイントQR → 撮影 → 写真確認・提出 → 判定結果 → マップ → ゴールQR → 結果

状態の復元、開始・終了の判断、QR検証、達成・加点、ゴール可否は共通側が決定します。プレイヤーUIでは、その結果を表示して操作を通知します。判定不成立からの再撮影、通信失敗からの再試行も同じ共通状態へ戻してください。

## 嶋本に必要な共通接続

| 場面 | 受け取るデータ | 通知する操作 |
|---|---|---|
| 参加 | 参加失敗の表示、復元した入力があれば初期値 | ルームコード・表示名で参加 |
| スタートQR | QRの受付状態・エラー | 読取内容を共通側で検証・受付 |
| 開始待ち | ルーム名・参加者名・開始時刻・残時間・再接続状態 | 接続の再試行 |
| マップ | フロアごとの案内図Widget（共通データの位置・達成状態を反映）、進捗、残時間、ゴール可否 | チェックポイントQR・ゴールQR・順位表示へ進む |
| 撮影 | 撮影指示、カメラプレビュー、撮影可能状態、エラー | 撮影・再撮影・写真提出 |
| 判定結果 | 処理中・成功・再撮影・エラーの表示状態、理由、共通側確定の加点表示 | 続行・再撮影・再試行 |
| ゴール | ゴールQR受付結果・共通側の終了状態 | ゴールQRを共通側で検証・受付 |
| 結果・順位 | 確定／集計中、得点・順位・内訳・並び順・自分の識別 | 順位表示・更新 |

QRは `PlayerQrView` の `scanner`、カメラは `PlayerCaptureView` の `preview` に注入します。読取・撮影Widgetの実装は松本の担当です。使用パッケージとAndroid権限／設定は嶋本と調整し、QR検証・写真の寿命・提出方法は共通側のインターフェースへ接続します。

`scanner` の読取イベントの重複抑止と停止・再開は読取機能側で必要です。UIのタッチ・読み上げ操作の無効化だけではカメラの読取イベントを止めません。フロアの案内図は4:3、カメラ／写真は3:4、QRは正方形の表示枠に入るため、注入Widget側で元画像の縦横比を保って表示してください。実コースと共通レイアウトが決まり次第、この表示枠も合わせます。

静的な案内図にはMapView側でズーム・移動を提供します。`InteractiveViewer` を直接渡す場合は二重に囲まず、そのWidget側へ操作を委ねます。独自Widgetの内部に拡大操作が隠れている場合は自動判別できないため、実接続時にジェスチャーの競合を確認してください。直接渡すViewerのフロア別表示位置を保持する場合は、注入側でフロア別Controllerを管理します。

同じViewを別コース・別ミッションに再利用する場合、親側で対象に対応する安定した `Key` を付けてください。写真確認では `photo.key` の切替でも拡大状態と古いエラー表示を初期化します。表示文字列やキーなしの任意Widgetから、対象データの同一性は判断しません。共通側での操作受付・重複防止も別途必要です。

各Viewは親の `Scaffold` 等に渡すbodyです。利用可能な領域・日本語フォント・文字拡大を継承し、body内にナイト配色を適用します。親のAppBar・システムバー・ルーターは変更していません。統合時は嶋本側で背景色とヘッダーの重複を調整してください。フロア選択・表示位置・写真の拡大状態・フォーム入力・送信中表示をUI内で保持します。保存・同期は行いません。

順位の失敗理由などは既存の `statusLabel` に共通側の案内を渡してください。文字列からエラーの種類や最終更新時刻を推定せず、未提供の状態・情報は追加表示しません。
