# プレイヤー画面と共通基盤への接続（松本）

`player_flow_page.dart` の `PlayerFlowPage({super.key, this.resumeRoomId})` が入口です。`resumeRoomId` はホームの「続きから」で渡すルームID、新規参加では null にします。Scaffoldを持たないbodyで、外枠・背景・戻るボタン・SafeAreaは嶋本担当の `PlayerShell` に任せます。

各Viewへ渡す値と操作を、既存の共通Repository・Provider・SessionStoreへ接続しました。親ルートはこの変更に含めていないため、アプリから開くには嶋本側で仮画面を差し替えてください。

## 入口の組み込み（C-9・M-1への回答）

`PlayerShell` 内の仮画面を次のbodyへ差し替えてください。親ルート・Shell自体はこの担当では変更していません。

```dart
import '../features/player/player_flow_page.dart';

PlayerFlowPage(resumeRoomId: resumeRoomId)
```

利用する共通接続は次の通りです。

| 接続 | 用途 |
|---|---|
| `matchRepositoryProvider` | 参加コード検索・参加・QR検証・写真提出 |
| `roomSnapshotProvider(roomId)` / `tickerProvider` | 開始・終了・参加状態・残時間・達成状況の表示と復帰 |
| `sessionStoreProvider` / `activeSessionProvider` | 共通のプレイヤー復帰記録の保存・再取得・結果を閉じる時の削除 |
| `hasClearedAllRequired` / `standingsOf` / `snapshot.scoreOf` | 共通側のゴール条件・順位・得点をそのまま表示 |

ルームを保存・複製せず、UI内では画面位置・現在の撮影対象・提出前の写真・操作中の状態だけを保持します。結果を閉じる際は、そのプレイヤーの対象ルームと一致する復帰記録だけを削除します。保存・削除の失敗には個別の再試行を用意しています。

## 今回のブラッシュアップ

選択された「ナイトミッション」案を、参加・開始待ち・マップ・QR・撮影・写真確認・判定・順位・結果へ反映しました。既存の公開コンストラクタ・引数・コールバック・判定状態enumを維持しています。`PlayerPage` には任意の見出し表示設定だけを追加しています。

| デザイン | 実装 |
|---|---|
| 基本配色 | 濃紺 `#071B28`、ライム `#D8F16A`、シアン `#86D5E2`。エラーはコーラルと文言・アイコンで表示 |
| 担当専用テーマ | `player_night_style.dart` に色・入力・ボタン・文字の定義。`PlayerPage` のbody内へ適用し、親のフォント・文字拡大を継承 |
| 探索の雰囲気 | 薄い図面グリッド、細線のパネル、コンパス、QR／撮影枠のガイド、ミッション達成バッジ |
| マップと結果 | 残時間をライムで強調、進捗を小さめに整理、フロア選択・自分の順位・確定／仮結果を明示 |

装飾はFlutter標準の描画・アイコンだけで実装しました。画像・フォント・依存関係の登録追加はありません。注入された実案内図・カメラ映像・写真の色は加工しません。TEMPデモの設計図風マップはサンプル描画で、会場の案内図ではありません。

前回の8分野の改善も維持しています。

| 分野 | 変更内容 |
|---|---|
| 情報整理 | 参加の入力案内、お題、残時間・進捗、判定後の行動、仮／確定結果を整理 |
| 部品の見た目 | `player_ui.dart` に担当専用のページ・カード・状態表示・情報パネルを集約 |
| 操作の配置 | 通常の高さでは主操作を下部に固定。高さ不足・文字拡大時は本文と一緒にスクロール |
| マップ操作 | 1〜4倍の拡大縮小・パン・全体表示、フロアごとの表示位置保持、フロア追加削除への追従 |
| 写真確認 | 中央を基準とする拡大縮小・パン・全体表示。表示操作で提出写真を変更しない |
| 状態表示 | 撮影準備・撮影中・提出中・失敗・再接続・順位更新・仮集計を区別。既存の表示データだけを利用 |
| アクセシビリティ | 見出し、状態通知、フロア選択、自分の順位の読み上げ、確認中QR操作の除外、文字拡大対応 |
| 担当テスト | 既存8件を維持し、ズーム・失敗・遅い応答・キーボード・読み上げ・小画面等を追加 |

フォーム入力・失敗時の写真・送信中の連打抑止は維持しました。お題や写真が差し替わっても、元の撮影／提出処理が終わるまで操作抑止を維持し、前の処理のエラーを新しい表示へ混ぜません。

## 固定コースの接続順

参加 → スタートQR → 一斉開始待ち → マップ → チェックポイントQR → 撮影 → 写真確認・提出 → 判定結果 → マップ → ゴールQR → 結果

上記は現在の `test-1` の共通APIで接続済みです。不合格は再撮影、通信失敗は同じ写真で再送できます。ルーム終了・時間切れ・自分のゴールを結果表示に優先し、遅れて返った撮影や判定で探索画面へ戻しません。復帰時はルームの共通状態からスタートQR・待機・マップ・仮結果・最終結果を選びます。

## QR・撮影（M-2への回答）

- `player_media.dart` は登録済みの `mobile_scanner` と `image_picker` を使用します。追加パッケージ・権限の依頼はありません。
- QRは読取ごとに停止して共通Repositoryで検証し、失敗時は「もう一度読み取る」で再開します。バックグラウンド移行・操作中・破棄時にも停止／解放します。
- 「撮影する」で端末のカメラを開きます。長辺1280px以内・品質80で取得し、確認画面には縦横比を保って表示、提出する元バイト列は拡大表示で変更しません。
- `playerPhotoPickerProvider` と `playerQrScannerBuilderProvider` は端末境界のテスト差し替え用です。ルーム・判定・保存の独自モックは追加していません。
- 写真はメモリ内だけです。Androidが撮影中にプロセスを破棄した場合、ルームへ復帰して再撮影します。プロセスを越えた未提出写真の復元は未対応です。

## 仮コース・フロア（M-3への回答）

`lib/core/mock/sample_course.dart` とRepositoryのコースを利用します。実館内図・地点座標は未提供のため、`player_course_map.dart` にフロア別の地点一覧・指定／自由・共通の点数・達成状況を表示します。「実際の館内図は未登録」と明示し、位置や経路は作っていません。自由ミッションも同じコースの任意チェックポイントを一覧し、共通QR・撮影・提出へ接続します。

静的な案内図にはMapView側でズーム・移動を提供します。`InteractiveViewer` を直接渡す場合は二重に囲まず、そのWidget側へ操作を委ねます。独自Widgetの内部に拡大操作が隠れている場合は自動判別できないため、実接続時にジェスチャーの競合を確認してください。直接渡すViewerのフロア別表示位置を保持する場合は、注入側でフロア別Controllerを管理します。

同じViewを別コース・別ミッションに再利用する場合、親側で対象に対応する安定した `Key` を付けてください。写真確認では `photo.key` の切替でも拡大状態と古いエラー表示を初期化します。表示文字列やキーなしの任意Widgetから、対象データの同一性は判断しません。共通側での操作受付・重複防止も別途必要です。

各Viewは利用可能な領域・日本語フォント・文字拡大を継承します。入口ではPopScopeで内部画面からマップへ戻し、提出中・端末記録の更新中の離脱を抑止します。探索中に親へ戻る場合は共通の復帰記録を残します。
