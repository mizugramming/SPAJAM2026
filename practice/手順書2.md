# 🧪 SPAJAM リハーサル手順書

ここでは、SPAJAM本番を想定してチーム全員でアプリ開発の練習をします！

目的はアプリを完成させることだけではなく、

- アイデアを決める
- 役割分担する
- GitHubを使って複数人で開発する
- 実機で動かす
- 発表する

という**本番の流れを一通り経験すること**です。

---

# 1. 【全員】リハーサル用ブランチを取得する

リーダーがブランチを作ったら、全員が自分のPCに反映します。

```bash
git fetch origin
git switch rehearsal/01
git pull origin rehearsal/01
```

今いるブランチを確認したい場合は、

```bash
git branch
```

を使います。

`*`が付いているものが現在のブランチです。

---

# 2. 役割分担を決める

誰が何を担当するかを決めます。

例：

| 担当 | 内容 |
|---|---|
| エンジニア① | 画面・アプリ基盤 |
| エンジニア② | API・DB・主要機能 |
| オールラウンダー | UI実装・テスト・開発補助 |
| 発表担当 | Figma・スライド・発表 |
| リーダー | 進行・仕様決定・全体確認 |

ただし、担当に関係なく困っている人がいたら助け合います。

---

# 3. 自分の作業ブランチを作る

各自、`rehearsal/01`から自分の作業ブランチを作ります。

まず最新にします。

```bash
git switch rehearsal/01
git pull origin rehearsal/01
```

その後、自分のブランチを作ります。

```bash
git switch -c feature/作業内容-自分の名前
```

例：

```bash
git switch -c feature/camera-matsumoto
```

```bash
git switch -c feature/result-mizuki
```

```bash
git switch -c feature/api-nagamatsu
```

---

# 4. 開発する

自分の担当機能を実装します。

作業中は、できるだけ他の人と同じファイルを編集しないようにします。

例えば、

```text
features/
├── camera/
├── result/
└── ai/
```

のように担当ごとに分けて作業すると、Gitのコンフリクトを減らせます。

---

# 5. ある程度できたらGitHubへ送る

変更内容を確認します。

```bash
git status
```

問題なければ、

```bash
git add .
git commit -m "カメラ撮影機能を追加"
git push -u origin feature/camera-matsumoto
```
↑ 例なので自分の形式に合わせてください

コミットメッセージには何をしたか書きます。

```text
⭕ 結果画面を追加
⭕ API通信処理を追加
⭕ ボタンが反応しない問題を修正

❌ 修正
❌ 更新
```

---

# 6. Pull Requestを作る

GitHubでPull Requestを作ります。

このとき、

```text
feature/自分のブランチ
        ↓
rehearsal/01
```

になるようにします。

> ⚠️ Merge先を`main`にしないように注意！

内容を確認して問題なければMergeします。

---

# 7. Mergeされた内容を取り込む

他の人の機能がMergeされたら、自分のPCにも反映します。

```bash
git switch rehearsal/01
git pull origin rehearsal/01
```

その後、自分の作業を続ける場合は再び自分のブランチに移動します。

```bash
git switch feature/camera-matsumoto
```

必要に応じて最新の`rehearsal/01`を取り込みます。

```bash
git merge rehearsal/01
```

コンフリクトが出た場合は、分からないまま進めずチームで確認します。

---

# 🚨 リハーサル中のGitルール

- `main`では直接作業しない
- `rehearsal/XX`でも直接作業しない
- 必ず`feature/〇〇`ブランチを作る
- Pull RequestのMerge先を確認する
- 作業前に必ず`git pull`
- 分からなくなったらまず`git status`
- コンフリクトが出たら勝手に進めない

特に以下は、分からない状態では使わないでください。

```bash
git reset --hard
git push --force
git clean -fd
```

# 🎯 リハーサルの目標

完成度100%を目指す必要はありません。

一番大切なのは、

**「チーム全員で時間内に、説明できるアプリを完成させる流れを経験すること」**

です。

失敗したところは、次のリハーサルで改善していきましょう！
